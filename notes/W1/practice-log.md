## Day 5（周五 11.20）权限 + WSL（可选）
- 做了：用 ls -l 逐字段读 README.md / notes/；拆解 -rw-r--r-- 与 drwxr-xr-x；
       算 644 / 755 / 600 / 750；自测三题（错 2 题后订正）；WSL 按建议跳过
- 卡点：把目录的 r 和 x 搞反了（以为 r-- 能 cd 进去）；以为 644 的脚本能直接 ./ 运行；
       一开始没想通 9 位为什么是 3 组
- 收获：10 位 = 1 位类型（- 文件 / d 目录 / l 链接）+ 9 位权限；9 位 = 3 组 × 3 位，
       依次是 u 所有者 / g 同组 / o 其他人，每组固定 r→w→x 顺序，缺权限写 - 占位；
       r=4 w=2 x=1 相加得 644 / 755。
       关键：同一个字母对文件和目录含义不同 —— 目录的 r 是"灯"（ls 列名字），
       x 是"门"（cd 进去），所以目录必须有 x。
       644 脚本直接 ./ 会 Permission denied，要先 chmod +x（W2 写 shell 脚本的前置）。
       600 是 ssh 私钥 / API key 的硬性要求，设 644 会报 Permissions are too open 拒绝连接。
       Windows / Git Bash 的权限是模拟的，真实语义等 W2 装 WSL 后验证。
